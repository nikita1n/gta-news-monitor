# GTA news monitor

Telegram-бот, который присылает новые публикации с четырёх сайтов:

| Сайт | Откуда берутся новости |
|---|---|
| [Rockstar Newswire](https://www.rockstargames.com/newswire) | GraphQL `graph.rockstargames.com` (тот же запрос, что в маршруте [RSSHub](https://github.com/DIYgod/RSSHub/blob/master/lib/routes/rockstargames/newswire.ts)) |
| [Rockstar Intel](https://rockstarintel.com) | RSS `https://rockstarintel.com/feed` |
| [GTABase](https://www.gtabase.com) | RSS `https://www.gtabase.com/news/?format=feed&type=rss` |
| [GTA BOOM](https://www.gtaboom.com) | RSS `https://www.gtaboom.com/feed` |

Бот работает на Cloudflare Workers (бесплатный тариф) и проверяет сайты каждые 15 минут.
Сначала он жил на GitHub Actions, но там расписание срабатывало раз в 3–7 часов вместо 15 минут.

## Настройка

1. Аккаунт на [Cloudflare](https://dash.cloudflare.com/sign-up), затем `npx wrangler login` (в браузере нажать «Allow»).
2. `npx wrangler deploy` — создаёт воркер и хранилище KV для состояния.
3. Бот в Telegram: [@BotFather](https://t.me/BotFather) → `/newbot` → токен.
4. С каждого аккаунта, который должен получать новости, написать боту что угодно.
5. `node setup.mjs` — спросит токен, найдёт эти аккаунты, сохранит всё в секреты Cloudflare
   и пришлёт каждому тестовое сообщение.

Первая проверка ничего не присылает: она только запоминает текущие статьи, чтобы не завалить чат старыми.

## Как это устроено

- `worker.mjs` — точка входа на Cloudflare: по расписанию из `wrangler.jsonc` запускает проверку,
  состояние (какие статьи уже отправлены) хранит в KV.
- `check.mjs` — одна проверка: забрать источники, отправить новое в Telegram.
- `lib.mjs` — чистая логика (что новое, сбои, формат, разбор RSS и ответа Rockstar), покрыта тестами.
- `monitor.mjs` — локальный прогон для отладки, состояние в `state.json`.

Поведение:

- Новое определяется по id статьи, а не по дате: у Rockstar закреплённые посты стоят первыми.
- RSS разбирается регулярками, а не XML-парсером: полный парсер тратит ~14 мс процессора
  при холодном старте, а бесплатный воркер получает 10 мс. Нужны только заголовок, ссылка, id и дата.
- Если источник не отвечает 3 проверки подряд (~45 мин), придёт одно предупреждение,
  а когда он оживёт — «снова работает».
- Если Telegram не принял сообщение, неотправленные статьи уйдут при следующей проверке.
  Аккаунт, который заблокировал бота, просто пропускается.
- За один запуск уходит не больше 40 сообщений Telegram (лимит бесплатного воркера — 50 запросов),
  остальное — в следующий раз.

## Команды

```bash
npm test                         # тесты логики
npm run dry-run                  # локально: что было бы отправлено, ничего не шлёт
npx wrangler deploy              # выложить изменения на Cloudflare
npx wrangler tail                # смотреть логи воркера в реальном времени
```

Добавить сайт — новая строка в `SOURCES` в `check.mjs` (для RSS достаточно ссылки на ленту), затем `npx wrangler deploy`.
